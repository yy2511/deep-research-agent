# 后端 PR 学习

## 确认版本与范围

- 用 GitHub 连接器或 `gh pr view NUMBER --json url,baseRefName,baseRefOid,headRefOid,additions,deletions,files` 取得 PR 链接、目标分支的提交和 PR 的 HEAD SHA。
- 本地缺少提交时，用 `git fetch origin BASE_BRANCH refs/pull/NUMBER/head` 取回。用 `git diff --numstat BASE_SHA...HEAD_SHA` 核对范围和行数，按 [开发流程](../../../docs/开发流程.md#52-后端-pr-学习) 判断是否自动跳过。用户主动点名学习某个小 PR 时，按请求带学。
- 从 `git diff BASE_SHA...HEAD_SHA` 和该提交里的文件取证，例如用 `git show HEAD_SHA:路径` 看 diff 周边的实现。读 issue 或设计了解预期，再沿代码和测试核对实际行为。

## 先审查，再讲解

- 先报审查的 HEAD SHA 和结论。发现问题时，给出代码位置、触发条件和影响；有需要先修的问题，就把发现交回作者，更新 PR 后再带学。按仓库规则选用必要的离线测试，并说明实际验证到哪里。
- 默认用 L1 入门中文，按用户的节奏加深。挑出这次最值得学的 1–2 个知识点，每个都指向 diff 中具体的文件和函数。讲清请求或任务怎么走，这个改动解决了什么，如果省掉这步会发生什么。遇到必要的术语，用一句大白话解释。
- 用 1–2 句对照生产做法，说明目前在哪些条件下够用、什么变化会促使团队升级、常见的升级路径是什么。依据本次代码用到的条件来讲。

## 随堂测验与反馈

- 讲完在同一聊天出 1–2 道短选择题。用具体场景考因果，例如某一步失败后用户会看到什么。先给选项，等用户答后再给解析。
- 答对即可过关，给出简短原因。答错时解释容易混淆的那一步，给一道同一知识点的短题再试。用户说“不会，直接讲”时，直接给答案和原因，标记“已讲解（未验收）”，可以结束本轮。
- 同一个 PR 有新提交时，沿用审查聊天。记录结果前重查 PR 的 HEAD SHA；有变化就先复核新 diff，按受影响的内容补讲补测，给出当前版本的结果。

## 追加学习笔记

- 答题通过后，往主工作目录（`git worktree list` 第一项）的 [后端学习笔记](../../../docs/notes/backend-learnings.md) 追加条目。记录日期、PR 链接、实际审查的完整 HEAD SHA、文件与函数、学到的因果和生产环境的适用边界。重复复习同一个 PR 版本时沿用该条。
- 本轮在本地追加笔记即可，集中归档时走文档 PR。最后在对话里简短报本轮结果、版本和笔记位置。
