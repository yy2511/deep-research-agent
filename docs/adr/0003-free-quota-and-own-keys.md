# 0003：内测：免费额度限一个模型，另支持用户自带 key

- 状态：已被 [0007](0007-public-trial-github-login.md) 取代（2026-11-08）
- 日期：2026-11-05

## 背景

内测要让用户先体验，同时不能让平台无限承担模型和搜索费用。不同模型价格相差几十倍，按“通用 token 数”送额度不公平。

## 决定

- 注册需要邀请码。
- 每个用户有一份免费模型额度，只能用平台指定的一个模型，按该模型的 token 数计。
- 用户可以填写自己的模型 key；用自己的 key 时不扣免费额度。
- 网页搜索使用平台的 key，所有用户按搜索次数计额度，与是否自带模型 key 无关。
- 每次模型调用前检查剩余额度，调用后按服务商返回的实际用量扣减；同一用户并发研究时扣减必须是原子的，不会扣成负数。
- 研究中途额度用完，不直接报错，用已收集的材料交稿，并告诉用户原因。
- 用户的 key 加密存储，页面只显示打码形式，不出现在日志和接口返回中；key 失效或余额不足时明确提示用户，不改用平台 key。

## 考虑过的其他选择

- 平台统一付费、按金额计费：需要维护价格表和计费系统，内测阶段不需要。
- 只支持自带 key：体验门槛高，不利于内测。

## 代价与影响

- 新增的限制：免费额度只能用一个模型；搜索有次数上限；注册需要邀请码。具体数值上线前由用户确定。
- 平台指定的免费模型必须选会返回用量数据的服务商；部分中转不返回用量（见 `src/dra/llm.py`），这类服务商不能用于免费额度。
- 自带 key 的用量只显示 token 数；如显示金额，需另建价格表并注明是估算。
