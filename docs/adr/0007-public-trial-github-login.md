# 0007：对外开放改为“公开试用”：GitHub 登录、按次数限额，不做自带 key

- 状态：已接受（合并即接受）
- 日期：2026-11-08
- 作者：Claude Code
- 关联：#43、[阶段2-公开试用](../design/阶段2-公开试用.md)、取代 [ADR 0003](0003-free-quota-and-own-keys.md)、[ADR 0004](0004-known-providers-only.md)

## 背景

ADR 0003、0004 按“邀请制内测、长期使用的多用户产品”设计：每人一份按 token 计的免费模型额度，另可填写自己的模型 key，key 加密入库，只能选平台列出的服务商。

2026-11-08 用户明确了在线版的用途：**给 GitHub 仓库引流**。在线链接放在 README 里，让访客不下载代码就能看到效果、试问一个自己的问题、留下意见；想长期用、想用自己 key 的人，拉代码在本机运行（源码公开，本机填 key 没有任何限制）。

由此带来的约束：

- 访客从 GitHub 来，只有几十秒耐心，门槛要低；陌生人很少愿意把自己的 API key 粘贴到别人的网站上。
- 每次研究要几分钟、调用几十次模型和搜索，费用由平台（用户本人）承担，必须有硬上限。
- 线上机器只有 1.9 GB 内存（[总体方案 §9](../design/后端扩展总体方案.md#9-部署)）；运行代码、浏览器功能是按单人使用设计的，不能对陌生人开放（总体方案 §11）。
- 第 1 阶段已完成：账号、会话 Cookie（ADR 0005）、每人只看自己的数据、只有管理员能改全站设置。

## 评估标准

1. 访客门槛：从 README 点进来到问出第一个问题要几步。
2. 费用可控：最坏情况下一天花多少钱是否有上限。
3. 防滥用：一个人能不能轻易换身份刷次数。
4. 实现量：要新写多少后端和前端代码，能复用第 1 阶段多少。
5. 引流效果：是否把人带回 GitHub 仓库。

## 候选方案

| 标准 | A. GitHub 登录 + 按次数限额（不做自带 key） | B. 原 ADR 0003/0004：邀请码 + 按 token 免费额度 + 自带 key | C. 不登录，按 IP 限次 | 维持现状（只有邀请码注册，无限额） |
| --- | --- | --- | --- | --- |
| 访客门槛 | 点“用 GitHub 登录”一键授权；示例不登录也能看 | 要先拿邀请码，陌生访客基本进不来 | 最低，打开就能问 | 进不来 |
| 费用上限 | 每人每天 N 次 + 全站每天 M 次，最坏一天 M 次研究 | 每人 token 额度，人数不受控时总量不受控 | 全站每天 M 次，但会被少数人刷光 | 无上限 |
| 防滥用 | 一个 GitHub 账号一个身份，刷号成本高；出问题知道是谁 | 邀请码控制人数 | IP 易换（代理、手机网络），共享 IP 又会误伤 | 靠邀请码 |
| 实现量 | OAuth 登录 + 次数计数 + 试用功能收紧；复用第 1 阶段全部 | 加密存 key、服务商列表、按用户切换模型连接、token 原子扣减、额度用完交稿 | 计数简单，但需验证码等防刷 | 无 |
| 引流 | 访客已经登录 GitHub，顺手点 star；反馈走仓库讨论区 | 弱 | 中 | 无 |

## 决定

选 A。

- **登录**：新增“用 GitHub 登录”（OAuth），只申请公开资料，不申请邮箱和仓库权限；GitHub 返回的访问令牌用完即丢，不保存。邀请码 + 邮箱密码注册保留，用于熟人。
- **三种角色**：
  - `guest`：GitHub 登录的访客，受试用限制。
  - `user`：邀请码注册，不受次数限制，但不能改全站设置（同第 1 阶段）。
  - `admin`：管理员。
  管理员可用命令调整角色。
- **按次数限额**：试用访客每人每天 N 次研究（追问也算一次），全站访客每天合计 M 次；用完明确提示，并引导到本机运行。不按 token 计费，不做充值。
- **试用访客的研究**：
  - 固定用管理员指定的一个便宜模型，时间和调用次数上限更紧。
  - 只用网页搜索：关闭运行代码、浏览器、外部资料服务（MCP）、私域资料库和附件。
- **不做用户自带 key**：想用自己 key 的人在本机运行。ADR 0004（自带 key 的服务商白名单）随之不再需要；管理员配置的平台连接不受影响。
- **示例**：管理员挑几个已完成的研究设为示例，所有人（含未登录）只读可见，用来展示效果。
- **意见反馈**：跳转到 GitHub 仓库的讨论区（Discussions），不自建留言系统。

具体表结构、接口和数值见[设计文档](../design/阶段2-公开试用.md)。

## 代价

- 访客必须有 GitHub 账号才能试问。目标人群就是 GitHub 访客，可以接受；没有账号的人仍能看示例。
- 依赖 GitHub：GitHub 登录不可用时访客无法登录（已登录的不受影响，会话在本站数据库）。服务器需要能访问 `github.com` 和 `api.github.com`。
- 按次数而不是按 token 计：同样一次研究，花费可能差几倍。靠固定便宜模型和更紧的单次预算把每次的上限压住，接受这种不精确。
- 不做自带 key，学习路线里“加密存储密钥”这一课暂时没有了；以后真需要时再写 ADR。
- 示例对所有人公开：设为示例前要确认其中没有私人内容（设计文档规定只允许纯网页研究设为示例）。

## 何时重新评估

- 访客量大到“每天 M 次”很快用完，或者有人明确想付费、长期在线使用。
- 出现批量注册 GitHub 小号来刷次数的情况。
- 要对不在 GitHub 上的人群（如非开发者）开放。
- 需要开放运行代码或浏览器功能给访客（需要先重新设计隔离）。
