# 0008：管理员运营面板只提供汇总统计，不扩展私有研究读取权限

- 状态：草稿
- 日期：2026-11-12
- 作者：Codex
- 关联：[#60](https://github.com/yy2511/deep-research-agent/issues/60)、[管理员运营维护面板](../design/管理员运营维护面板.md)、[ADR 0005](0005-login-server-session-cookie.md)、[ADR 0006](0006-sqlalchemy-alembic-sync.md)

## 背景

管理员希望看到用户数和使用情况。当前 `require_admin` 管理配置，但 `readable_run` / `readable_conversation` 并不允许管理员读取其他人的非公开研究。运营概览无需改变这一合同。用户要求展示可公开信息，不是授权发布用户提问或身份。

## 评估标准

1. 能否回答用户数量与研究使用量的问题。
2. 是否避免采集/传输私有内容、保持现有权限边界。
3. 指标是否可从现有数据准确解释，不把未知当零。
4. 实施和运维成本，是否引入新服务或难以撤回的访问能力。

## 候选方案

| 标准 | A. 管理员汇总 API + 面板 | B. 管理员用户/研究明细列表 | C. 维持现状，通过服务器查库 |
| --- | --- | --- | --- |
| 用户数/使用量 | 满足，明确指标口径 | 满足，还提供个体详情 | 能查，但不直观且需服务器权限 |
| 隐私边界 | 不返回个人标识或研究内容 | 扩展跨用户读取，风险与审批负担高 | 无新网页权限，但运维直接接触原始数据 |
| 准确性 | 数据库登记口径，可重复测试 | 容易把文件/数据库状态混淆，需更多设计 | 依赖操作者 SQL，难统一 |
| 成本 | 新只读查询与页面，无外部依赖 | 还需明细分页、权限、审计等 | 无开发，重复人工成本高 |

## 拟议决定

选 A，仍待设计 PR 合并确认。使用现有管理员鉴权和同步 SQLAlchemy，只返回明确的聚合响应。现有研究读取接口不变，不返回 ID、身份、提问/答案/证据、每人维度或下钻链接。未登录和普通账号不能读取汇总；“聚合”不等于允许公开发布。

首版从现有数据库聚合，不遍历运行目录，不引入遥测采集或分析服务。运行成功率、费用、资源健康等缺乏统一结构化来源的指标明确不展示。完整接口、口径、异常与验收见设计文档。

## 代价

- 不能在面板里定位某个人的问题或阅读具体失败内容；那是另一个需要明确授权和权限设计的需求。
- 小样本精确计数不保证匿名化，因此只在管理员边界内使用；本次不虚构差分隐私保护。
- 大范围查询有性能成本；不擅自加硬上限。实施需测量，必要时另评估索引/预聚合。
- UTC 统计日期可能与试用额度配置时区不同，需要显著标注。

## 何时重新评估

需要对外公开、普通用户可见、个人筛选/明细、运行健康指标，或实测聚合性能影响主业务时。扩大权限/新增采集必须单独评审，不把本 ADR 当作访问所有研究的授权。本草稿不推翻已接受 ADR。
