# 0009：三级平台角色之外保留访客，支持个人免费次数管理

- 状态：已接受（设计 PR #65 已合并）
- 日期：2026-11-12
- 作者：Codex
- 关联：[#64](https://github.com/yy2511/deep-research-agent/issues/64)、[设计](../design/三级角色与用户管理.md)、[ADR 0007](0007-public-trial-github-login.md)、[ADR 0008](0008-admin-aggregate-dashboard.md)

## 背景

用户要求平台负责人、平台管理员、普通用户三个层级及网页用户管理，随后明确在三层外再加访客，访客由平台通用配置提供免费额度。因此保留guest，不将其并入user，也不新增用户未要求的使用档位。

## 评估标准

符合最新身份要求、最小权限、迁移不自动提权、试用成本可控、负责人不被锁死、并发计数可靠、SQLite/PostgreSQL可验证。

## 候选方案

| 方案 | 优点 | 代价/风险 |
| --- | --- | --- |
| 维持guest/user/admin，仅CLI | 改动小 | 不满足最高负责人和网页用户管理 |
| 仅owner/admin/user，访客变使用档位 | 权限与套餐分离 | 不符合用户最新明确的额外访客身份 |
| owner/admin/user/guest，访客全局、普通用户个人额度（选定） | 四种身份可理解，保持现有访客保护 | 新owner治理、个人额度及并发台账 |

## 决定

用户于2026-11-12已明确确认仅一位负责人、个人额度按日计算，并要求进入实施。设计 PR #65 已合并；实现按 #66 推进，不授权修改真实账号或部署。

增加唯一active owner，部署维护者显式初始化，owner原子移交，禁止自动认领。owner任免admin；admin管理user/guest状态、有限个人额度及两者转换，但不能授予无限。guest仍仅用全局trial额度，无个人覆盖。user有每日有限或无限策略，旧user迁移保留不限次数。guest升级user的admin操作须同事务配置有限额度并确认能力变化。

接受后仅部分取代ADR0007的三角色和CLI独占管理决定，保留GitHub登录、不自带key、访客功能与全站额度和公开示例。ADR0008的汇总和私有研究隔离不变；账号管理明细只给授权管理者，不在汇总API添加身份明细。

## 代价

新增治理记录、角色和个人额度迁移、原子扣次台账、审计及重新认证。负责人任免权限不能委托普通admin；无限额度需owner。旧不限额用户历史使用不完整，不能伪造回填。实际生产负责人由部署维护者确认，不从GitHub仓库身份推断。

## 何时重新评估

需要多负责人、组织/租户、终身余额/月度套餐、付费计费或更细的平台设置权限时重做设计，不把每日次数直接当货币余额。
