# 设计文档

设计文档写“具体怎么做”：数据模型、接口、流程、出错时怎么办、怎么验收。“为什么选这个方案”写在 [ADR](../adr/README.md)，设计文档里链接过去，不重复争论。何时必须写、写作规矩见 [开发规范 §7](../开发规范.md#7-设计文档与-adr)。

## 状态

| 状态 | 含义 |
| --- | --- |
| 草稿 | 在写或在评审，未合并 |
| 已接受 | 设计 PR 已合并，可以按它写代码 |
| 已实施 | 代码已合并，“实施记录”已补全 |
| 已废弃 | 不再按它实施，写明原因或被哪份取代 |
