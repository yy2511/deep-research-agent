# 三级平台角色、访客与用户管理

- 状态：草稿，设计合并后再实施
- 日期：2026-11-12
- 作者：Codex
- 关联：[#64](https://github.com/yy2511/deep-research-agent/issues/64)、[ADR 0009](../adr/0009-platform-roles-and-user-quotas.md)

## 目标与不做什么

提供平台负责人（owner）—平台管理员（admin）—平台普通用户（user）三个管理/成员层级，并在三层之外保留访客（guest）。用户最新要求：访客使用平台通用配置中的免费额度；普通用户可单独配置免费使用次数。在“平台管理”增加用户管理，角色分配不再只靠命令行。

本设计不改线上账号、不猜测谁应成为负责人，不提供充值或付费账单，不查看用户提问、报告、证据、密码或令牌，不增加研究数据读取权限。设计 PR 不包含实现，也不授权部署。运营汇总独立沿用 [运营面板设计](管理员运营维护面板.md)，本设计扩展账号管理，不把账号明细混入汇总接口。

## 现状

- [User](../../src/dra/db_tables.py) 角色为 guest/user/admin，状态为 active/disabled；GitHub 新账号为 guest，邮箱邀请码账号为 user。
- [trial.for_user](../../src/dra/api/services/trial.py) 只限制 guest：研究含追问，每日计数；规划另计；同时扣个人及全站访客额度。user/admin 当前不限次数。
- [admin CLI](../../src/dra/admin.py) 可改角色、停用账号，网页无用户管理；[deps](../../src/dra/api/deps.py) 从服务端会话解析当前权限，私人研究仅本人可读。

## 1. 身份与权限

| 操作 | 平台负责人 owner | 平台管理员 admin | 普通用户 user | 访客 guest |
| --- | --- | --- | --- | --- |
| 运营汇总、现有平台配置 | 是 | 是 | 否 | 否 |
| 分页查看必要账号身份/状态/额度 | 是 | 是 | 仅本人 | 仅本人 |
| 启停普通用户、访客 | 是 | 是 | 否 | 否 |
| 配置普通用户有限个人额度 | 是 | 是 | 否 | 否 |
| 任免管理员、停用管理员 | 是 | 否 | 否 | 否 |
| user↔guest转换 | 是 | 是，须确认能力/额度变化 | 否 | 否 |
| 授予普通用户无限额度 | 是 | 否 | 否 | 否 |
| 移交负责人 | 仅本人 | 否 | 否 | 否 |
| 读取他人非公开提问/报告/证据 | 否 | 否 | 否 | 否 |
| 资源策略 | 现有管理能力，不限次 | 现有管理能力，不限次 | 个人配置；旧账号默认不限次 | 全站试用配置 |

owner是唯一且有效的平台负责人；admin不能管理自己、其他admin或owner，不能通过修改角色成为owner。普通用户和访客无平台管理入口。访客仍是已通过GitHub登录的账号；未登录匿名访问者不是数据库角色，只能访问公开示例，不能研究。

admin将guest升级为user时必须同时明确有限个人研究/规划额度，不得默认获得无限使用；owner可以选择不限次。此转换解锁原有user研究能力，界面列出代码/浏览器/MCP/资料等变化并要求确认。admin把user降为guest后，该账号只走全局访客策略；原个人额度不生效，但可保留记录供再次升级时确认。owner任命admin也必须明确确认该角色具备全站配置与不限次数能力，不能将任命管理员当作送次数的快捷操作。

owner只能通过专门移交改变自身角色；通用修改接口拒绝owner/本人。无硬删除账号、批量提权、批量清空使用量或公开导出功能。管理员可看其他管理者的身份行，但无编辑按钮；服务端必须独立校验。

## 2. 负责人初始化、迁移与恢复

新增Alembic迁移，不改历史迁移：角色约束增加owner，原guest/user/admin不变，身份、OAuth绑定、研究归属和每日计数不变。不自动把最早账号、GitHub仓库创建者或任意admin升为owner。

新增platform_governance单例记录：owner_user_id（初始化前可空）、version。无owner时显示“尚未设置平台负责人，请联系部署维护者”；既有admin保留现有功能，owner专属操作不可用。

部署维护者执行显式CLI `dra-admin bootstrap-owner --user-id <ID>`：先只读查看候选ID/显示名/角色/状态，人工核对；要求目标为active现有admin、当前owner为空，事务内原子比较更新治理记录和User.role。不得自动执行，不提供公开“抢占负责人”API。两个初始化请求只能一个成功。目标旧会话撤销，重新登录生效。

有owner时bootstrap拒绝。owner在界面移交给另一active admin：原owner降为admin，二者旧会话撤销，同一事务提交。弹窗明确目标，当前owner须近期重新验证身份。密码账号校验当前密码但不记录；OAuth重新认证必须是绑定的同一provider subject，不把另一账号登录当确认。验证证明绑定当前会话、本次目标、governance version和双方management_version，单次使用，默认5分钟过期（部署可配置；界面显示到期时间，以服务端UTC为准）。原会话撤销、角色变化、治理版本变化或到期立即作废，拒绝移交并要求重新验证；复用现有登录安全流程，不增加GitHub权限。

事故恢复用部署维护者专门CLI，显式填写原owner、目标ID、原因和确认，执行同样锁与审计；通用set-role不得绕过唯一负责人保护。真实账号变更仍需操作者确认，本PR不执行任何初始化/移交。

升级先停旧服务写入、备份、迁移、启动新版，不混跑新旧服务。回滚旧schema前人工处理owner、个人额度及审计备份，不能静默降权或删历史。SQLite/PostgreSQL迁移与约束需一致。

## 3. 访客全局额度与普通用户个人额度

### 访客

沿用当前全站trial配置：个人每日研究/规划上限、全站访客合计上限、时区、固定模型及单次预算。研究首问/追问各算一次；规划另计。只允许网页来源，关闭代码、浏览器、MCP、私域资料和附件。个人剩余=min(个人上限−已用, 全站访客上限−已用)。

访客详情只读显示“额度来源：平台通用配置”，不提供个人覆盖；修改访客策略应跳转平台配置并提示影响所有访客。无例外访客无限额度。GitHub初次登录仍创建guest，重复登录不能覆盖已有角色。

### 普通用户

第一版个人免费次数按每日，不是终身余额/月套餐，研究与规划分别配置；不把一次研究内的模型/工具调用多扣次数。个人额度不受访客全站池限制、不消耗该池。

新增user_quota_policies：user_id唯一、mode（limited/unlimited）、daily_runs_limit、daily_briefs_limit、version、updated_by、updated_at。limited需两个非负整数，0禁止该种新调用，不能表示无限；unlimited两字段为空。无任意产品数量上限，数值范围与数据库整数表示能力一致，越界报错不截断。

旧user迁移为unlimited，以保留现有行为；GitHub仍guest，邀请码注册仍user/unlimited。注册策略不在本设计擅自改变。admin可把user改为有限额度或调整有限额度，但仅owner能授予/恢复unlimited。guest由admin升user必须同事务设置limited，owner可以显式选择unlimited。无有效策略的user为配置异常503，不静默退回无限。

user降为guest或升为admin时个人策略不生效，但保留审计及配置；重新成为user须显式确认策略。owner将admin降user时同事务明确有限/无限策略；降guest时立即走访客策略。未变更角色的普通user，日常额度调整不得清空已用量。

日界沿用trial设置中的既有时区，普通用户页面同样明确显示时区与下次重置时间。全站时区调整影响两类计数日界，界面提示影响；新设计采用负责人确认、下一旧时区日界生效的切换规则，记录边界，防止反复切换立即刷新额度。这是“管理员可修改现有平台配置”的明确例外：通用设置接口也必须在后端拒绝admin修改时区，不能仅隐藏按钮。具体实现需固定时钟测试，不改变已占位台账日期。

## 4. 原子计数、变更和退款

DailyCounter用户计数延续，不因角色/策略变化清零。guest的user:<id>与guests历史计数保持；原不限额用户无完整历史计数，升级当日明确显示“从升级时起计数”，不能伪造历史。

新版本所有新研究/规划都记录个人每日使用，包括不限额管理者/普通用户；只有guest同时消耗guests全站池。升降级不能重置个人已用数：guest↔user切换当天共用同一个个人计数，改变的是有效上限及后续全局池扣次。

新增统一配额服务。研究/规划都在占位事务中锁当前用户、策略与计数行，重新读取有效role/status、policy version和当日计数。锁顺序固定（用户ID排序、个人再全局），SQLite用等价串行写事务。个人/全站扣次及研究占位一起成功或回滚，最后一次只有一个并发请求成功。请求开始时的旧角色快照不能授权新的扣次。

策略更新要求expected_version，冲突409带最新内容供重看；更新与占位使用同一用户串行化边界。修改提交后的新占位用新政策；此前已提交占位继续，不中断运行中研究。降低上限到已用以下，剩余0、后续429；提高立即增加剩余，但不清空使用记录。

新增quota_reservations台账：run_id或规划请求幂等键唯一、user_id、kind、quota_day、实际扣过的scope列表、policy version、状态。启动前失败按原台账退回个人/全局计数至多一次，角色后来改变也不改变退款池。已开始后失败/取消、规划调用失败不退，保持既有合同。规划重传同一幂等键不重复扣，主动新规划新键算新请求；复用运行已有幂等语义，不把模型内部重试当新研究。

## 5. 页面与API

“平台管理”含“运营概览”“用户管理”“平台配置”；owner额外见“负责人管理”。身份称谓统一为平台负责人/平台管理员/平台普通用户/访客。

```text
平台管理  [运营概览] [用户管理] [平台配置]
用户管理  搜索账号____  身份[全部] 状态[全部]
账号/ID    身份      额度来源    今日研究已用/上限   状态  操作
示例 42    普通用户  个人设置    2/5                正常  查看/编辑
示例 51    访客      平台通用    1/2                正常  查看/编辑
[上一页] [下一页]

详情抽屉：身份只读字段、角色、状态、免费次数
普通用户：[有限次数] 研究每天___ 规划每天___
负责人可选：[不限次数]
访客：由平台通用配置决定（只读） [查看平台配置]
[保存] [取消]，角色/状态/次数变更分别明确确认
```

移动端表格变卡片，详情同抽屉，不挤压横向列。邮箱、GitHub显示名、稳定内部ID仅供授权管理者识别，无密码/哈希/token或研究内容；不在管理页添加私有研究查询链接。搜索仅账号必要身份，分页可持续翻页，不限制平台总用户数。

| 接口 | 权限/合同 |
| --- | --- |
| GET /api/admin/users | owner/admin，cursor+身份/状态/账号过滤，稳定ID排序，只必要身份/额度摘要 |
| GET /api/admin/users/{id} | owner/admin，账号详情，无研究数据 |
| PATCH /api/admin/users/{id}/status | owner管admin/user/guest；admin只管user/guest；expected_version |
| PATCH /api/admin/users/{id}/role | owner任免admin、转换user/guest；admin仅user↔guest；升user同时指定策略 |
| PUT /api/admin/users/{id}/quota | owner/admin按权限矩阵；只接受user；expected_version |
| POST /api/admin/owner-transfer | 仅当前owner，active admin目标，近期重新认证、governance version |
| GET /api/admin/audit-events | owner查看全部管理审计；admin仅user/guest管理范围，分页 |

/API/me扩展角色显示和本人额度状态，guest沿用trial状态；user展示个人模式、已用、剩余、重置时间。管理统计须适配owner维度，与独立运营面板PR协调，不能让新owner被旧role检查误挡。

User新增management_version（非负整数）；角色/状态请求必须匹配此版本，成功原子递增。角色转换同时涉及配额时，提交management_version与quota version，在一个事务校验并更新二者；重复请求/旧版本返回409。治理移交同时校验governance version与双方management_version，更新治理、角色、会话撤销及审计一起提交。

所有接口使用require_db和当前有效会话，写接口沿用same_origin及Cookie防护。分别定义请求schema，拒绝未知字段和任意User批量赋值。401未登录/失效；403越权（先检查调用者）；404合法范围目标不存在；409版本冲突；422非法参数；429额度耗尽；503数据库/策略不可用。

管理响应Cache-Control:no-store；无公共缓存，日志不记录搜索词/邮箱/表单正文/身份凭证。审计存actor/target ID、动作、允许的before/after、UTC时间、原因和请求标识，不含密码/token/研究内容；变更和审计同事务。审计网页不可编辑，无自动删除期，本设计不改变现有保留规则。

角色/状态变化撤销目标旧会话，重新登录后生效；额度日常调整不强制登出，/api/me刷新后显示，服务端占位立即遵守。每次写入在事务内按ID顺序锁actor/target并重新核验角色，防止被降级管理员在并发窗口继续写。owner通用修改永远拒绝，即使有人直接构造请求。

前端保存期间禁重复点击；成功刷新账号行和权限入口。401重登录、403清理失效管理页面、409展示最新值重选；取消/返回不保存；不同用户详情请求用取消/序列号防旧响应覆盖；移交成功退出原owner，不残留最高权限入口。

## 6. 验收矩阵

| 场景 | 预期 |
| --- | --- |
| 迁移旧guest/user/admin | 原角色不变、user明确unlimited、旧计数/身份/研究归属不变 |
| GitHub新登录/重复登录 | 新guest，已有账号角色不被覆盖 |
| 两人bootstrap | 仅一个owner，无公开抢占接口 |
| user/guest直接请求管理API | 401/403，无账号明细泄漏 |
| admin管理自身/admin/owner或授予无限 | 拒绝，不因隐藏按钮代替后端检查 |
| guest个人配额写入 | 拒绝，明确全局策略来源 |
| admin将guest升user | 强制明确limited，列出能力变更并审计 |
| owner移交并发/重放/失败 | 全事务，唯一active owner，旧验证不能复用 |
| 并发降权与管理写请求 | 重新鉴权，降权提交后不能继续越权写 |
| 个人最后一次/全局最后一次 | 原子扣次，其他请求429，不超额 |
| 上下调个人额度、跨日、换角色 | 不清零已用，时区/重置可解释 |
| 占位后换身份并启动失败 | 原池退款至多一次，不按新身份错退 |
| 私有研究访问 | owner/admin也不能越权读取 |
| 双击/取消/返回/搜索竞态/键盘 | 无重复写入、无串用户、焦点清楚 |
| SQLite/PostgreSQL迁移和并发 | 相同约束与结果，备份可恢复 |

实施拆分为：迁移/治理/权限；配额与台账；界面与审计；运营汇总兼容。每阶段独立实现issue/PR，设计合并前不写代码；页面不能先发布无后端保护的按钮。需运行登录、试用、研究回归与新增SQLite/PostgreSQL测试，浏览器测试按仓库规则获得许可，不使用生产数据。

## 新增的限制与待定事项

新增唯一负责人、管理对象层级、管理员不能授予无限、移交重新认证及审计。保留访客全局每日限额和能力收紧、私有研究隔离。不增加用户总数上限。每日而非终身额度是第一版方案，实际数值由管理者配置；不虚构默认次数。用户于2026-11-12明确确认“只设置一位负责人，个人额度按日计算”。这两项已定；若以后需要多负责人或终身额度，应先调整设计。

ADR0009只部分替代ADR0007的三角色/CLI独占管理，保留访客全局试用规则。ADR0008继续约束汇总和私有研究；新增账号管理不代表能查看私人问题。
