# 开发规范

日期：2026-11-05。这里写代码层面的约束；流程见 [开发流程.md](开发流程.md)，重大决定见 [adr/](adr/README.md)。

## 1. 分层

后端扩展完成后的目标结构：

```text
src/dra/
  api/routers/      接口层：解析请求、校验身份与权限、调用业务层、组装响应
  api/services/     业务层：任务、额度、用户等业务规则
  api/repositories/ 存储层：读写数据库与文件
  worker/           执行研究任务的独立进程
  （其余模块）       研究引擎：检索、阅读、子 Agent、存证、交稿
```

依赖方向只能向下：

```text
routers → services → repositories
worker  → services / repositories / 研究引擎
研究引擎 → 不依赖 api、worker、web
```

- 接口层不直接读写数据库或文件，经过业务层。
- 研究引擎不知道“用户”“额度”这些平台概念；需要的配置由调用方传入。
- 现状：接口和业务目前都在 `src/dra/web.py`，后续按 issue 分步拆分。研究引擎目前不依赖 `dra.web`，这一点已经满足，后续保持。

## 2. 接口

- 路径用 `/api/<资源复数>`，动作用 HTTP 方法表达：`GET /api/runs`、`POST /api/research`、`DELETE /api/library/documents/{id}`。
- 错误用 FastAPI 的 `HTTPException`，返回 `{"detail": "..."}`，`detail` 写成用户能看懂的中文。
- 接受异步任务的接口返回 `202` 和任务 ID，不等任务完成。
- 新接口在 PR 描述里列出路径、参数和返回示例。

## 3. 数据库（引入后生效）

- 表结构变更全部用迁移脚本，不手工改库。
- 已经合并到 `main` 的迁移脚本不修改，只新增。
- 迁移要能在空库和已有数据的库上都跑通。
- 长事务里不调用模型、搜索等外部服务。

## 4. 测试

- 默认离线：`uv run pytest`。真实模型（`--run-live`）、Docker（`--run-docker`）、浏览器（`--run-browser`）需用户同意。
- 新功能和修 bug 附测试；修 bug 的测试应在修复前失败、修复后通过。
- 前端：`npm --prefix web test`、`npm --prefix web run lint`、`npm --prefix web run build`。

## 5. 代码检查

- 当前 CI 用 ruff 检查语法错误和未定义名称（`E9,F63,F7,F82`），全仓库通过。
- 更多规则（未使用导入等）以单独的 issue 逐步开启，每次开启时同时清理存量问题。

## 6. 限制与密钥

- 不自行添加需求未要求的上限、截断、白名单或静默降级；确需添加时先说明影响，并在 PR 的“影响的限制”一栏列出。
- 密钥只放 `.env` 或受控运行配置；不写进源码、测试夹具、文档、日志和 PR。

## 7. 设计文档与 ADR

两种文档分工：

| | ADR（[docs/adr/](adr/README.md)） | 设计文档（[docs/design/](design/README.md)） |
| --- | --- | --- |
| 回答 | 为什么选 A 不选 B | 具体怎么做 |
| 粒度 | 一个决定一份 | 一个功能或阶段一份 |
| 写完后 | 基本不改，推翻时新写一份取代 | 实施中随代码更新，做完标“已实施” |

何时必须写：

| 情况 | 要写 |
| --- | --- |
| 在几个方案间选择，且以后不好改（技术选型、架构、安全策略、新增限制） | ADR |
| 新增表、接口、进程，改数据格式，或跨多个模块 | 设计文档 |
| 新增依赖或组件（如 Redis） | ADR，并在设计文档写清用法 |
| 修 bug、小改动、行为不变的重构 | 都不用，issue + PR 即可 |

需要写的 issue 打 `需要设计` 标签。设计文档单独开 PR，合并后再写代码。

写作规矩：

1. 区分测过的和猜的。数字注明来源（如“本机 49 份日志实测”），没测过的标“假设”。
2. 候选方案必须真实考虑过，不摆明显不行的方案凑数；“维持现状”通常应列入。
3. 先写评估标准，再比较方案。
4. 代价照实写；写清“何时重新评估”。
5. 实施时偏离设计，在同一个 PR 里更新设计文档，并在“实施记录”说明原因。
6. 引用代码写到文件和函数名，方便核对。
