# 研究规则清单

这份清单列出一次研究从开始到交稿，后端会做的所有检查：每条拦什么、为什么有、代码在哪、由哪个测试保护。

- **位置**写的是“文件 · 函数名或报错原文”，在代码里搜这段原文就能找到。没写行号，因为行号一改代码就会变。
- **分类**：A 类是这个项目的根本，应该保留；B 类有道理，但写得太复杂或太死；C 类是针对某一次事故打的补丁，建议评估后删除或改成提醒。
- 分类是 2026-09-28 整理时给出的建议，**还没有按建议改动任何行为**。

除特别说明，代码都在 `src/dra/simple_research.py`。

## 一次研究的流程

```text
你提问
 → 判断要不要先问你几个问题（澄清）→ 生成研究计划 → 需要时请你确认
 → 主 Agent 循环：搜索 / 阅读 / 保存证据 / 派子任务 / 更新计划
      每一轮开始前：停止了吗？超时了吗？连续没进展吗？额度用完了吗？
      每个工具执行前：参数对不对？允许做吗？
 → 交稿：正文、引用、覆盖说明逐项检查
 → 结束：再查一次引用，算出“已完成 / 部分完成 / 未完成”
```

## A 类：根本规则，应保留

| 规则 | 用大白话说它拦什么 | 为什么有 | 位置 | 保护它的测试 |
|---|---|---|---|---|
| 先读后引 | 证据里的原话必须出自 Agent 真正读过的那一段原文，服务端逐字比对位置 | 防止模型编造或改写引文 | `ToolContext.save_evidence`；报错原文“先 read_source 精读来源”“请先在当前Agent中read_source该原文再存证” | `test_simple_research.py`（`unread_evidence_is_rejected`、`forged_excerpt_number_is_rejected`）、`test_quote_binding_rules.py` |
| 交稿时查引用 | 回答里的 `[c3]` 必须对应真实存在的证据卡，否则打回让它改，最多打回 2 次 | 当场指出，模型还能自己改；事后才发现就只能整份降级 | `_unknown_citation_reason`、`_MAX_CITATION_REPAIRS` | `test_finish_draft.py`、`test_budget_wrapup.py` |
| 结束时查引用 | 再查一次：引用了不存在的卡、一张卡都没有、或一处引用都没写，都会降级为“部分完成”并写明原因 | 引用对不上，回答就没法追溯到原文 | `citation_gate` | `test_simple_research.py`、`test_web_research_e2e.py`、`test_evidence_judge.py` |
| 研究总时限（可选） | 默认不限时；在设置里打开后，剩 120 秒时提醒 Agent 交稿（工具照常能用），到点还没交稿就记为未完成、保留已有材料 | 你想控制时长时用；不开就由 Agent 自己交稿或你叫停 | `SimpleConfig.wall_timeout_s` / `wrapup_reserve_s` | `test_timeout_recovery.py`、`test_settings_save_contract.py` |
| 停止立即生效 | 你点停止后，这一轮的检索、存证、交稿都不再执行；迟到的模型回复也不产生新动作 | 停止就是停止，不能停了还在花钱、改结果 | 研究循环里的 `llm.cancellation_requested()` 检查 | `test_cancellation.py`、`test_async_web.py` |
| 网站黑名单 | 用户在“来源”里填的网站：检索结果里剔除，也不许按网址读取；读回时如果被跳转到黑名单网站，正文作废（已发出的请求照实记账） | 用户明确不想用的来源不能混进证据；评测时也靠它屏蔽题目的原始文章 | `src/dra/site_filter.py`；`ToolContext._retrieve`、`_read_source`、`_extract_doc`；报错原文“网站黑名单” | `test_site_blocklist.py` |
| 仅查资料时不上网 | 选了“仅我的资料”，就不允许读网页、不允许连外部资料服务（MCP） | 尊重你选的研究范围，资料可能不该和外网混用 | 报错原文“本次仅研究所选资料，不允许读取网页”“仅资料模式不允许外部 MCP” | `test_library_research.py`（`only_library_blocks_scope_and_url...`）、`test_mcp_research.py` |
| 子任务不能再派子任务 | 子 Agent 不能再派发子任务；同一时刻最多 3 个子任务在跑，多的排队 | 防止无限套娃、防止打爆第三方接口的限流 | 报错原文“子 Agent 不允许递归派发”；`_SUBAGENT_MAX_PARALLEL` | `test_simple_delegation.py`、`test_research_delegation_async.py` |
| 模型回复不完整就不动手 | 网络断在一半、模型回复没收完整时，一个工具都不执行 | 半截参数可能是错的，不能拿去调用外部服务 | 报错原文“模型流式回包不完整，未执行任何工具” | `test_llm_stream_tools.py`、`test_finish_and_trace.py` |
| 交稿前处理完新消息 | 你中途补充了要求，主 Agent 必须先读到并处理，才能交稿 | 你的补充不能被跳过 | 报错原文“有新的用户消息到达，先在下一轮读取并处理” | `test_user_steering.py`（`pending_steer_blocks_stale_finish...`） |
| 交稿前处理完子任务 | 还有子任务在跑或有没读的子任务消息时，主 Agent 不能交稿 | 子任务的成果不能丢 | 报错原文“还有未读取消息或活跃子任务” | **没有专门测试**（只被其他子任务测试间接覆盖） |

## B 类：有道理，但可以简化

| 规则 | 拦什么 | 问题在哪 | 位置 | 测试 |
|---|---|---|---|---|
| 参数格式检查（约 40 处） | query 为空、range 写法不对、编号不存在…… | 本身该有，只是报错话术各写各的，可以统一 | 所有以 `_ERR +` 开头的返回 | 分散在各测试中，例如 `test_find_and_range_args.py` |
| 调用次数上限 | 开启“限制调用次数”后，模型和工具的调用次数有上限 | **默认关闭**。一旦开启，会连带下面两条一起生效，逻辑分散在好几处 | `SimpleConfig.max_llm_calls` / `max_tool_calls`；设置页“限制调用次数” | `test_call_limits_observation.py`、`test_budget_wrapup.py` |
| └ 最后几次只许存证 | 工具额度只剩 2 次时，检索和阅读都被拒，只允许保存证据 | 同上 | `SimpleConfig.tool_reserve_calls`；搜“降落保留区” | `test_budget_wrapup.py`、`test_run_edge_cases.py` |
| └ 额度用完后的收尾 | 研究停了但还没交稿时，额外给一次“只许交稿”的机会；接着原对话写，看过的材料都还在 | 同上 | `_wrapup_turn` | `test_budget_wrapup.py`、`test_open_research_limits.py` |
| 同一个搜索词不许搜第二次 | 同一个 query 第二次搜会被直接拒绝 | 可能误伤正当的重搜，改成提醒更合适 | 报错原文“已经搜过，请换角度” | **没有专门测试** |
| 单次最多存 50 张卡 | 一次保存证据最多 50 张 | 只防“一次写入无限条”，合理；数值依据见代码注释 | `SimpleConfig.max_cards_per_call` | `test_cancellation.py` |

## C 类：单次事故的补丁，建议评估后删除或改成提醒

| 规则 | 拦什么 | 来历 | 位置 | 测试 |
|---|---|---|---|---|
| “正文见上”检测 | 交稿正文不到 400 字、且以“正文见上”“完整答案见上文”开头时拒收 | 有一次模型把答案写在过程说明里，交稿只写了“（正文见上）”，所有检查都通过了，用户拿到空壳 | `_pointer_draft_reason` | `test_finish_draft.py`、`test_completion_web.py` |
| 快用完额度时不许重复回读同一张卡 | 开启次数限制、额度进入最后几次时，已经完整回读过的证据卡不能再读 | 为了不让回读占掉存证的额度 | 报错原文“保留区内已完整回读这些卡” | `test_run_edge_cases.py`（`inspection_cannot_consume_reserved_saving_slots`） |
| 空正文的两种提示 | 交稿正文为空时拒收，并按“参数解析失败”和“真的没写”给不同提示 | 有一次参数 JSON 解析失败，正文被读成空串 | 报错原文“finish_research 的 draft 不能为空” | `test_cancellation.py`、`test_call_limits_observation.py` |

## 2026-09-29 改为“只丢写错的部分、能修就修”

原来这些地方只要模型写错一处，就整份作废甚至让整步失败。现在的处理：

| 位置 | 原来 | 现在 | 测试 |
|---|---|---|---|
| 研究计划 / 缺口判断的原问题 | 要求模型逐字抄写，抄错一个字整步失败 | 服务端直接用自己保存的原问题 | `test_research_brief.py` |
| 研究计划的编号 | 中文、带空格、重复的编号让整份计划作废 | 合规的沿用，不合规的由服务端重编 | 同上 |
| 研究计划的要求类型 | 规定之外的类型让整份计划作废 | 认不出的按“目标”处理 | 同上 |
| 研究计划的“要不要确认” | 写成字符串让整份计划作废 | 按字面意思转换，看不懂时保守地要求确认 | 同上 |
| 研究计划的路线 / 前提 / 缺口问题条数 | 超出上限整份作废 | 只保留前面的条目 | 同上 |
| 修订计划时的要求编号 | 没变的要求换了编号就报错 | 按内容对回上一版的编号 | 同上 |
| 交稿时的覆盖说明 | 错一条丢全部 | 只丢写错的那条；常见近义状态（如 `partially_answered`、`已回答`）自动归一 | `test_finish_coverage.py` |
| 交稿时的缺口清单 | 一条不是文字就丢全部 | 写成对象的把文字拼出来保留 | 同上 |
| 交稿时的最终任务清单 | 一条不对丢全部 | 只丢写错的条目；近义状态归一；编号不合规重编；一条都救不回来时保留上一版 | 同上 |
| 强制收尾时的范围变更 | 写错连正文一起丢 | 忽略写错的范围变更，正文照收并留下说明（正常研究回合仍打回，模型可改好再交） | 同上 |

## 2026-10-07 取消的规则

| 原规则 | 现在 |
|---|---|
| 连续 3 轮没进展就停 | 取消。命令报错、读取或存证失败都把原因交给模型，由它修正、换方法或交稿；等子任务也不算失败 |
| 每轮最多 20 次 Bash 命令 | 取消。只统计次数，和其他工具一样服从你设置的总时间、总调用次数 |
| 剩 120 秒时撤掉工具、只许交稿 | 改成提醒，工具照常可用，总时限不延长 |
| 收尾时换成只有证据卡的新对话 | 接着原对话收尾；只有原对话装不下或还没开始研究时才用证据卡单独收尾 |

| 数值 | 默认 | 位置 |

## 已知问题（还没处理）

- **给模型的说明太长**：主 Agent 每一轮都要读约 5300 字、126 行、含 29 条“必须 / 不许”的说明（`_LEAD_SYSTEM`）。规则越多越容易被违反，违反了又去加代码拦截，是规则越积越多的主要原因。精简它需要用真实模型对比验证。
- **下载的报告里混着内部状态**：`render_markdown` 生成的报告末尾会写“停止原因：cancelled、交付状态：failed、Lead 自报…”。网页已经不把它当回答显示，但报告文件里还有。
- **研究主循环太长**：`run_lead_loop` 一个函数约 800 行，所有检查都在一长串 if 里。
