# 评测计划

这份计划回答四个问题：报告写得好不好、引用靠不靠谱、跑得稳不稳和花多少钱、检索（RAG）准不准。每项写明测什么、怎么测、现状和成本。评测都是独立的离线工具，只打分，不接入研究流程、不拦截回答。

真实模型、付费搜索和评分都要花钱，每次跑之前先确认范围。

## 总览

| # | 评测 | 回答什么 | 状态 | 成本 |
|---|---|---|---|---|
| 1 | DeepResearch Bench II（中文题） | 报告质量：该查到的查到没有、有没有分析、表达是否合格 | 已跑通，2 题试跑 | 高：每题研究约 400–600 万 token，评分约 4 万 token |
| 2 | 引用可信度（自建） | 引用是否撑得起那句话 | 待做 | 低：评分每份报告 5–10 万 token |
| 3 | 运行统计（自建） | 成功率、失败原因、耗时、用量 | 待做 | 无 |
| 4 | BrowseComp-Plus | 检索器与 Agent 框架各自的贡献（Agentic RAG） | 首选的主实验评测集，待做 | 中：先 30 题试跑，正式 100 题以上 |
| 5 | BrowseComp-ZH | 难找信息的查找能力（中文、真实联网） | 补充 | 中 |
| 6 | RACE（DeepResearch Bench） | 洞察力、可读性等主观质量 | 可选 | 高 |
| 7 | 资料库检索（QASPER） | 本地资料检索的命中率 | 暂缓 | 无（本机） |

建议顺序：3 → 2 → 1 扩到 10 题 × 2 次 → 4 → 对比实验。

## 评测集怎么选（2026-09-30 调研）

| 评测集 | 题数 | 使用程度 | 排行榜 | 可信度 |
|---|---|---|---|---|
| BrowseComp（OpenAI） | 1266 | 最广，几乎所有大厂发布模型都报 | 第三方汇总各家自报（llm-stats 67 个模型、BenchLM 45 个） | 各用各的框架与搜索，条件不统一；头部已 90% 以上接近饱和；题目公开一年多，可能被模型记住 |
| BrowseComp-ZH | 289 | 国内厂商普遍报（DeepSeek、通义、智谱、Kimi、MiniMax、字节） | 第三方汇总自报 | 同上 |
| BrowseComp-Plus | 830 | 研究圈为主，检索公司常用来打榜 | 有官方排行榜（Hugging Face：Tevatron/BrowseComp-Plus），区分标准框架与自定义框架 | 文档库固定、官方评分脚本统一、可复现；论文被 ACL 2026 主会录用 |
| LiveBrowseComp | 335 | 很新（2026-05 预印本） | 未找到官方排行榜 | 答案来自出题前 90 天的新信息，专门排除凭记忆作答；尚未经过时间检验 |

结论：原版 BrowseComp 最权威、最常用，适合当行业参照，但不适合证明框架价值；**证明“同一个模型下我们的框架更好”，首选 BrowseComp-Plus**，BrowseComp-ZH 作中文、真实联网的补充；LiveBrowseComp 可作“是真的在搜”的加分项。

以上各项之上，下面的“同模型、多框架对比”是**核心实验**：证明分数来自我们的框架，而不只是模型本身强。BrowseComp-Plus、简答模式、思考预算都是为它服务的部件。

## 核心实验：同一个模型，多个框架

**要回答的问题**：“这个分数是模型强，还是框架有用？”只报一个总分回答不了，必须固定模型，只换框架。

**配置**：全部用同一个模型（如 deepseek-v4.1-flash）、同一套搜索工具、同样的时间与次数上限。

| 配置 | 做法 | 说明什么 |
|---|---|---|
| B0 闭卷 | 不给工具，直接问模型 | 凭记忆能答对多少，作为地板 |
| B1 一次检索 | 用原问题搜一次，读前几篇，直接作答 | 最朴素的 RAG |
| B2 最简 Agent | 单 Agent 循环：搜索、阅读、作答；无子 Agent、证据卡、引用检查 | 常见的 ReAct 式写法 |
| B3 第三方框架 | 开源框架接同一模型。首选 BrowseComp-Plus 官方仓库自带的标准 Agent（支持 OpenAI 兼容接口，对应排行榜的“标准框架”）；其次 Pi-Serini（Question's Gambit 论文用的先进框架）、LangChain open_deep_research（均需核实能否接入所用模型） | 和别人的框架比，不只和自己搭的基线比 |
| 我们的完整框架 | 主 Agent + 子 Agent + 证据卡 + 引用检查 | |
| 逐项拆除 | 完整框架上逐个关闭：不派子任务、不用证据卡等 | 每个设计各自贡献多少 |

**指标**（不只看最终分数）：

1. **同模型增益**（主指标）：我们的框架比 B2、B3 高多少分。
2. **记忆答不出的题上的正确率**：先用 B0 闭卷跑一遍，去掉凭记忆就能答对的题，只在剩下的题上比较。把模型记忆与框架能力分开，回应 LiveBrowseComp 的质疑（Agent 是在搜，还是在验证已知答案）。
3. **有据可查的正确率**：答对且答案被引用原文支撑，与“答对但属于猜中”分开统计。这是证据卡与引用检查的价值所在，其他框架多半给不出。
4. **过程指标**：证据召回率（人工标注的证据文档找到多少，仅 BrowseComp-Plus 可算）、搜索次数、每题耗时。
5. **成本效率**：每答对一题的 token 与花费，画“正确率 - 成本”对比图（参照 HAL）。多花钱正常，要看换来多少正确率。
6. **稳定性**：同题跑 2–3 次，同时报“至少一次答对”和“每次都答对”的比例。

**保证结论站得住**：

- 同一批题在所有配置下都跑，逐题成对比较，不只比两个总分。
- 至少 50 题，每个配置 2 次。
- 评测集：首选 BrowseComp-Plus（文档库固定，可算证据召回率）；BrowseComp-ZH 作补充（真实联网、中文，贴近实际使用）。
- 先定题目和评分规则再跑，不看结果换题。已人工试玩的 6 题只作开发集，报分用没碰过的测试集。

**现成参照**（Question's Gambit 论文表 1，已核对原文）：Pi-Serini 框架 + BM25 检索，deepseek-v4-flash 68.1%、deepseek-v4-pro 71.4%、gpt-5.5 83.1%（全部 830 题，每题 900 秒）。我们用 v4.1-flash + 同样的 BM25 跑出来可大致对照；需写明模型版本、时间上限的差异。

**第一步**：B0 闭卷在 BrowseComp-ZH 上跑一遍（不搜索，花费很少），看 deepseek-v4.1-flash 凭记忆能答对多少，决定“记忆答不出的题”这个子集有多大。

**预期可说的结论**：同一个模型，在只靠记忆答不出的题上，最简 Agent 答对 X%、开源框架 Y%、我们的框架 Z%；我们答对的题中 W% 能追溯到原文证据；拆除实验给出每个设计的贡献。

## 1. DeepResearch Bench II（中文题）

- **测什么**：专家文章拆出的是/否检查项，分信息召回、分析、表达三类，逐条判断报告有没有写到。
- **怎么测**：`eval/drb2/`。研究用 `run_pilot.py`，题目给出的原文网址进网站黑名单，评测脚本另按标题拦截转载页；评分用 `judge.py`，调用官方评分代码（GPT-5.5），只把请求改为流式。
- **现状**：idx 15、43 两题试跑，详见 `eval/drb2/README.md`。发现同一配置两次运行分数可差 10 分以上，单次结果说明不了问题。
- **下一步**：固定 10 道中文题（跨领域），每题跑 2 次，报平均分和波动范围。
- **局限**：只衡量“和专家文章像不像”，写了专家没写的正确内容不加分；不检查引用真假。

## 2. 引用可信度（自建，DRB2 测不到）

用同一批报告，不另跑研究：

| 指标 | 怎么测 | 花钱 |
|---|---|---|
| 原话是否出自原文 | 证据卡原话与原文快照逐字比对 | 否 |
| 引用是否撑得起那句话 | 报告中的一句话 + 它引用的全部原话（附少量上下文）交给评分模型，判完全支持 / 部分支持（指出缺在哪）/ 不支持；不给卡片上模型写的结论 | 少 |
| 该有引用却没引用的句子 | 评分模型把无引用的句子归类：标题、过渡、分析推断、常识、有具体事实却没出处 | 少 |

- 同时按 DeepResearch Bench 的 FACT 口径（部分支持也算支持）再算一遍，便于和公开数字大致对照；再单独报告“部分支持”的比例和原因。
- **检验评分模型本身**：故意把引用换成无关卡片、改掉原文数字，看能否判为不支持；人工抽查 30 条看一致率。
- 已见到的实例：医学题第二次运行把“他从论文中了解到”这一推断写成确定结论并挂了引用，引用只证明论文存在。

## 3. 运行统计（自建，不花钱）

从每次运行的记录汇总：完成 / 部分完成 / 停止 / 失败比例与原因、耗时、模型调用次数、输入输出 token、搜索与阅读次数、子任务数、证据卡数、存证被拒次数。每跑一批评测，这张表跟着出来。旧记录缺字段时显示“缺数据”，不当成 0。

## 4. BrowseComp-Plus（Agentic RAG 评测）

论文：BrowseComp-Plus: A More Fair and Transparent Evaluation Benchmark of Deep-Research Agent（arXiv 2508.06600，2025 年 8 月，滑铁卢大学 Jimmy Lin 等；已被 ACL 2026 主会录用）。数据 CC BY 4.0，见 texttron.github.io/BrowseComp-Plus；代码 github.com/texttron/BrowseComp-Plus。它本质上是一个 Agentic RAG 评测：固定文档库 + 可替换检索器 + Agent 自主多轮检索。

**做法**：把 BrowseComp 的实时网络搜索换成固定文档库，检索器成为可替换、可比较的部件。

- 题目：BrowseComp 1266 题中，去掉 o3 找不到证据、抓取失败的，1005 题人工核验后保留 830 题。
- 文档库：100195 篇。每题平均 6.1 篇证据文档（支撑整条推理链）、2.9 篇答案文档（直接含答案）、76 篇干扰文档（用 GPT-4o 拆出子问题后谷歌搜索前 100 条）。14 名标注员、400 多小时，交叉一致率 80% 以上。平均每篇约 5000 英文单词。
- Agent 工具：搜索返回前 5 条，每条截取前 512 token；可选“读全文”工具。作答需标 [文档编号] 引用，按“解释 / 最终答案 / 把握程度”格式输出。
- 比较对象：5 种检索器（BM25，Qwen3-Embedding 0.6B/4B/8B，ReasonIR-8B）× 11 个模型（GPT-5、o3、GPT-4.1、gpt-oss、Claude Opus 4/Sonnet 4、Gemini 2.5 Pro/Flash、Qwen3-32B、Search-R1-32B）。
- 指标：正确率、证据召回率（搜索返回过的文档覆盖多少标注证据）、搜索次数、校准误差；检索器单独看 nDCG@10、Recall@5/100/1000。
- 评分模型：论文用 GPT-4.1；官方现已改用开源的 Qwen3-32B（官方称两者平均相差不到 1%），评分脚本在本地 GPU 上运行 Qwen3-32B，另保留 GPT-4.1 评分脚本供参考。

**主要结果**：

| 模型 | BM25 | Qwen3-Embedding-8B |
|---|---|---|
| GPT-5 | 55.9% | 70.1% |
| o3 | 49.3% | 63.5% |
| Gemini 2.5 Pro | 19.0% | 28.7% |
| Qwen3-32B | 3.5% | 10.4% |

- 检索器越好，正确率越高、搜索次数越少（GPT-5：23.2 → 21.7 次）。
- 直接给出证据文档时 GPT-4.1 答对 93.5%、Qwen3-32B 答对 83.3%：瓶颈在“边想边搜”，不在推理。Qwen3-32B 平均每题搜索不到 1 次。
- 加读全文工具：GPT-4.1 35.4% → 43.6%。
- GPT-5 跑完 830 题 API 费用约 360–400 美元。

**排行榜现状**（用户 2026-09-30 截图，前 18 名）：

- 分“标准框架”（只用官方搜索函数）与“自定义框架”两类。官方基线 GPT-5 + Qwen3-Embed-8B 标准框架 71.69%。
- 前几名：AI21 95.18%（GPT-5 + 混合检索，自定义，每题平均搜索 209 次）；Sail Research 90.72%（GLM-5.1 + BM25/Qwen3-Embed-8B 混合，自定义）；Mixedbread 90.48%（GPT-5 + 自家检索，自定义）；Hamidi Rad 等 90.48%（GPT-5.5 + BM25 + Question's Gambit，自定义）；LightOn 87.59%（GPT-5 + 自家 Reason-ModernColBERT，自定义；同组合标准框架 79.52%）。
- 按做法分：检索公司训练自家检索模型的最多（LightOn、Mixedbread、TopK、AgentIR）；也有不训练、只用现成组件做框架的，且排在前面（Sail Research、Question's Gambit、openJiuwen、Agentica、爱丁堡大学）；通义 DeepResearch-30B 是专门训练的 Agent 模型。
- 榜上都是强模型（GPT-5/5.5、GLM-5.1、gpt-oss），没有 DeepSeek Flash 这类便宜模型。我们的目标是同模型对比，不是冲排名；若要上榜需用强模型跑全部 830 题，费用需先估算。
- 同一检索器只换框架的公开先例：GPT-5 + Reason-ModernColBERT，标准框架 79.52%，自定义框架（只多一个读全文函数）87.59%，搜索次数 19.3 → 13.3。

**不训练、只做框架的两个前排做法**：

1. **Question's Gambit**（arXiv 2609.14412，2026-09-13 预印本，多伦多大学、滑铁卢大学等，代码开源于 github.com/radinhamidi/Question-s-Gambit；已下载原文核对）
   - 问题：开局冷启动。Agent 首次搜索只能用整个问题，多条件谜题的条件搅在一起，早期只命中部分条件就被带偏，后续每一步都建立在开局之上。
   - 做法（只替换 Agent 的第一步，运行一次）：
     1. 拆线索：用 Agent 自己的模型把题目里的条件逐条列出（平均 9.6 条），线索只作检索单位，不作子问题逐个回答，可并行检索；
     2. 逐条检索并按文档库措辞改写：先用线索原文检索得到参考文档，改写模型（MUGI，固定用 GPT-4.1）参照这些文档把线索改写成文档库实际使用的词，而不是模型记忆里的说法；再以“线索 + 改写 + 原问题”拼成查询，用 BM25 检索；
     3. 合并去重（约 2500 篇），用 Cohere Rerank 对照完整问题重排，取前 5 篇作为开局材料；
     4. 之后沿用 Pi-Serini 框架原有的检索、预览、翻页、阅读四种操作，每题 900 秒。
   - 结果（Pi-Serini → 加开局检索，均显著）：GPT-5.5 83.1% → 90.5%；GPT-5.4-mini 68.1% → 79.0%；DeepSeek-v4-pro 71.4% → 76.9%。开局每题多花约 0.05 美元（整题约 0.55 美元），Agent 发起的搜索次数基本不变。
   - 错误分析：GPT-5.5 答错的 79 题中，正确文档没搜到的只占 3.8%，搜到但没点开看的占 55.7%，看了没引用 11.4%，读了仍答错 29.1%。瓶颈已从“搜不到”变成“搜到了不会挑”。
2. **Sail Research**（2026-04 公司博客，推销其推理服务，非论文，数字未独立核实）
   - 做法：指挥 Agent（GLM-5.1）只提搜索词、做判断和作答，**自己不读任何文档**；每次搜索返回的文档交给一群便宜的读者 Agent（gpt-oss-120b）并行阅读，丢弃无关文档、提炼证据；指挥只看提炼结果，决定继续搜还是作答。
   - 用量：830 题中指挥共用约 3900 万 token，读者约 64 亿 token（平均每题约 780 万，几乎全在读者）；按其自家价格每题约 0.15 美元，换其他服务商 1–5 美元。
   - 对照：同样用 gpt-oss-120b + Qwen3-Embed-8B，照搬官方现成做法只有 57%。

**对我们的启发**：

- 框架确实能拉开差距，而且不用训练，这是我们能参与的赛道。
- Sail 的“强指挥 + 便宜读者”与我们的主 Agent + 子 Agent、以及“主 Agent 强模型、子 Agent 便宜模型”的设想一致；区别是他们的指挥完全不读原文，我们的主 Agent 会自己读。
- Question's Gambit 的“拆线索、逐条检索、按文档库措辞改写”即前面设想的谜题式问题搜索策略，且直接针对凭记忆猜答案，可借鉴其开源代码。
- 除证据召回率外，再统计“搜到的正确文档实际读了多少”：我们的运行记录里有每次读了哪些来源。

**我们怎么用**：

- 同一评测回答两个问题：
  - 检索设计：纯 BM25、纯向量、混合（我们资料库用 BM25 + BGE-M3 RRF）、混合 + 重排，谁让 Agent 答得更准、搜得更少；
  - 框架价值：固定检索器和模型，对比我们的主 Agent + 子 Agent 框架与论文的基础搜索 Agent，也可验证下文的对比实验。
- 接入：用研究代码的替换搜索函数（DRB2 评测已用过）接入文档库检索；我们的读原文工具相当于论文的“搜索 + 读全文”配置。
- 先用官方提供的现成索引测框架；要测我们自己的混合检索，10 万篇 × 约 3 万字符在本机建向量索引很慢，先取子集。
- 抽样 100–150 题；按我们每题几百万 token 的用量先估算费用。

**小批量测试步骤**：

1. 准备数据（不花钱）：用官方解密脚本得到题目、答案与证据/答案文档标注（题目加密发布）；从 Hugging Face 下载文档库（10 万篇，几个 GB）；下载官方现成的 BM25 索引（需 Pyserini 与 Java 21）。先只用 BM25：简单，且与上面 deepseek-v4-flash 68.1% 的参照条件一致。可能需要登录 Hugging Face。
2. 抽题：固定随机种子从 830 题抽 30 题做第一轮。30 题误差约 ±17 个百分点，只用于检查流程和发现明显问题；正式对比 100 题以上。
3. 接入（`eval/bcp/`，思路同 `eval/drb2/`）：
   - 替换搜索函数：查 BM25 索引，每条结果带前 512 token 摘要，并附全文供“读原文”使用（相当于论文的读全文工具）；
   - 断网：禁止按网址读取真实网页、不连外部资料服务，否则 Agent 可能上真实网络找答案，结果作废；
   - 跳过澄清，题目后附“解释 / 最终答案 / 把握程度”格式要求；时间上限改为 900 秒与论文对齐；
   - 每题按官方格式存 JSON：题号、各工具调用次数、是否完成、搜索返回过的全部文档编号、最终回答。
4. 评分：官方评分模型是 Qwen3-32B，官方脚本需要本地 GPU。替代方案按优先级：找提供 Qwen3-32B 的 API 服务（与官方评分模型相同）；或用 GPT-5.5 中转套同一评分提示词（需注明与官方不同）。指标：正确率、证据召回率、搜索次数、校准误差；另按 Question's Gambit 的方式做错误分类（没搜到 / 搜到没读 / 读了答错）。
5. 对照：第一轮只跑我们的系统，粗略对照 68.1%；第二轮用官方仓库的标准 Agent 接我们的 deepseek-v4.1-flash 跑同样的题，作为“同模型、标准框架”对照组。
6. 成本与时间：我们每题几分钟、几百万 token，30 题串行约几个小时；先跑 2–3 题看实际用量再估算整批费用。

建议顺序：先做不花钱的准备（下载数据、装 BM25、写接入脚本，用假模型离线跑通），再真实跑 1–2 题看用量。

**注意**：
- 题目来自 BrowseComp，模型可能凭记忆答对（LiveBrowseComp，arXiv 2605.28721，预印本，称无工具可答对最多 44.5%）；固定文档库挡不住这一点。
- 若不用 Qwen3-32B 评分，与官方数字会有出入，需注明。
- 需要按“解释 / 最终答案 / 把握程度”格式作答，并跳过澄清。

## 5. BrowseComp-ZH（可选）

289 道中文多跳查找题，答案短而客观，评分只比对答案（沿用 BrowseComp 评分模板）并算校准误差。出处：BrowseComp-ZH 论文（arXiv 2504.19314，2025-04，第一作者 Peilin Zhou；GitHub PALIN2018/BrowseComp-ZH），非 OpenAI 官方，但借鉴 BrowseComp 思路、题目由专家直接用中文编写并经百度/必应/谷歌验证；官方未划分训练/测试集，289 题即全部。2025 年论文里 OpenAI DeepResearch 42.9%、豆包深度搜索 26%。国内厂商普遍自报该指标（llm-stats 汇总）：字节 Seed 1.8 81.3%、Qwen3.5-397B 70.3%、GLM-4.7 66.6%、DeepSeek-V3.2 65.0%、Kimi K2-Thinking 62.3%、DeepSeek-V3.1 49.2%；通义 DeepResearch 自报 46.7%。均为各家用自己的框架测得。适合当“查找能力”的客观指标，但不测报告和引用。已从中抽 6 题做人工试玩（答案在会话临时目录，未入库）：游戏题、科技题答对；医学题两次一对一错；体育题结论对，但标题写成运动项目、给了 4 个候选，按严格评分可能判错。

**评分规则**：要求按“Explanation / Exact Answer / Confidence”三行作答；评分模型只从回答中抽出最终答案与标准答案比对，有任何不一致、歧义都判错；报告质量和引用不加分。

**适配方式**：不写针对题库的提示词（如“题目是倒推出的”），而是做成通用的“简答模式”产品功能：问题要一个具体答案时，最终输出先给一行明确答案和把握程度，有多个候选也选定一个，其余候选放在解释里；跑评测时只把这一行转成规定格式。格式只能挽回“答对却被判错”的题，真正决定分数的是搜索行为，按“格式 → 谜题式问题的搜索策略（先搜最有区分度的条件，逐条核对候选）→ 思考预算 → 多次运行汇总”逐项加，每项单独测贡献。

## 6. RACE（可选）

DeepResearch Bench 的报告质量评分：每题动态生成全面性、洞察力、指令遵循、可读性四维标准与权重，待测报告与参考报告并排按条打 0–10 分，得分 = 待测 ÷（待测 + 参考），50% 表示与参考持平。能评“有没有洞察”，但主观，评分模型的偏好影响大。

## 7. 资料库检索（QASPER，暂缓）

原项目 `review_runs` 里有 9 月的实验（QASPER 固定 32 题：纯向量与混合都命中 16/24，混合 + 重排 17/24）。需要时搬成可重跑的脚本，补纯 BM25 一组，本机跑、不花钱。BrowseComp-Plus 若做，可部分替代这一项。
