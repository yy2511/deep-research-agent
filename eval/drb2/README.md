# DeepResearch Bench II 试跑

用 DeepResearch Bench II（DRB2）的中文题跑研究，先只产出报告，**还没有打分**。

## 数据

- `data/tasks.jsonl`：DRB2 全部 132 题（中英各 66），来自 <https://github.com/imlrz/DeepResearch-Bench-II>，许可 CC BY 4.0，未做修改。
- 每题有：`content.task`（问题）、`content.rubric`（逐条的是/否评分项，分信息召回、分析、表达三类）、`content.blocked`（出题所依据的原文：标题、作者、网址，研究时不许用）。

模型、时限与 Web 当前运行配置相同。跳过澄清和计划确认，直接研究题目原文。

## 原文屏蔽

数据集的 `prompt` 字段在题目后面用英文写了“不许看这篇文章”。这里不靠提示词，改用代码强制：

1. 原文网址放进产品的**网站黑名单**：检索结果里剔除，也不许按网址读取，读取时跳转到这些网址同样作废。
2. 评测脚本另加一层**标题拦截**：检索结果或读回的页面，标题或正文开头出现原文标题就剔除，用来挡住转载页。这一层只在评测里有。

被拦的记录写在每题的 `meta.json` 的 `title_guard_hits` 里。

## 输出

`runs/<批次>/idx-<n>/`：

- `report.md`：正文加引用来源，以后交给评分模型用；
- `full.md`：产品导出的完整报告（含运行状态）；
- `meta.json`：模型、耗时、用量、证据数、黑名单、拦截记录。

## 打分

```bash
uv run python eval/drb2/judge.py --batch 20260929-pilot-2             # 只检查
uv run python eval/drb2/judge.py --batch 20260929-pilot-2 --run-live  # 调用 GPT-5.5 打分
```

评分提示词、分批、结果校验、算分都用官方仓库原代码（固定版本 `b38f3606`，放在 `.official/`）。与官方有两处差别，都不影响分数：请求改为流式，因为中转站前的 Cloudflare 100 秒没响应就断开（`official_runner.py`）；每批最多重试 3 次（官方 10 次）。结果在 `runs/<批次>/judge/`，`scores.md` 列出每条没拿到分的检查项和评分理由。

### 2026-09-29 结果（GPT-5.5，思考强度 medium）

| idx | 信息召回 | 分析 | 表达 | 总分 | 用了屏蔽原文 |
|---|---|---|---|---|---|
| 15 | 65.7%（23/35） | 20.0%（3/15） | 80.0%（4/5） | 54.5%（30/55） | 0 |
| 43 | 48.7%（37/76） | 45.5%（5/11） | 100%（5/5） | 51.1%（47/92） | 0 |

评分花费约 8.1 万 token。没拿到分的主要原因：

- **分析分低**：事实大多找到了，但没有写出因果和总结，例如“自动化常规任务 → 人手转去做高价值工作”。研究提示词要求交稿写成“发现清单”，每句都要有引用，模型因此很少写综合推断。
- **不肯推断**：idx 43 表格里有 14 处写了“原文未明确说明”，评分项要的优缺点多是专家综述的归纳，原论文里没有原话。
- **缩写理解错**：idx 43 把 ED 理解成 Evolutionary Dynamics，题目指的是 Exploitability Descent，这一行 4 条全丢。
- **时间范围**：idx 15 要求 2019–2023 年，报告引用了 2025、2026 年的资料，丢了一条表达分。

官方排行榜（132 题）上，多数产品的分析分高于信息召回分；我们这两题是反过来的。只有 2 题，不能直接和排行榜比较。
